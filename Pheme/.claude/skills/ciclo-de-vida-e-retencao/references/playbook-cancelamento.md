# Playbook de cancelamento — pesquisa de saída e ofertas de retenção

Tabelas de decisão para as etapas 2 e 3 do fluxo de cancelamento. A pesquisa de
saída é a fonte de dado mais valiosa que você tem: desenhe-a para gerar
inteligência usável, não só categorias.

## Pesquisa de saída → oferta (mapeamento 1:1)

| Motivo de saída | Oferta de retenção | Sinal por trás |
|---|---|---|
| Caro demais / preço | Desconto ou downgrade | Sensibilidade a preço |
| Não estou usando o suficiente | Dicas de uso + opção de pausa | Falha de adoção |
| Falta uma funcionalidade | Mostrar roadmap + alternativa | Lacuna de produto |
| Indo para um concorrente | Comparativo competitivo | Posição de mercado |
| Projeto acabou / sazonal | Opção de pausa | Necessidade temporária |
| Complicado demais | Ajuda de onboarding + suporte humano | Fricção de UX |
| Só testando / nunca precisei | Sem oferta — deixe ir | Encaixe errado |

**Regra:** cada motivo mapeia para exatamente UMA oferta. Mapeamento ambíguo =
oferta genérica = taxa de salvamento baixa.

## Oferta de retenção → quando usar / quando NÃO usar

| Tipo de oferta | Quando usar | Quando NÃO usar |
|---|---|---|
| Desconto (1-3 meses) | Objeção de preço | Problema de adoção ou de funcionalidade |
| Pausa (1-3 meses) | Sazonal, projeto acabou, não usa | Objeção de preço |
| Downgrade | Caro demais, uso leve | Objeção de funcionalidade |
| Trial estendido | Não explorou o valor todo | Power user saindo |
| Liberar funcionalidade | Falta recurso que existe em plano superior | Plano errado |
| Suporte humano | Complicado, travado, frustrado | Objeção de preço (não gaste tempo do CS) |

## Regras de apresentação da oferta
- Um título claro: "Antes de ir — [oferta]".
- Quantifique o valor: "Economize R$X", não "ganhe um desconto".
- Sem contadores regressivos a não ser que algo realmente expire.
- CTA claro: "Resgatar oferta" vs. "Continuar cancelamento".

## Categorias de motivo — princípios de desenho
- Múltipla escolha de 6-8 motivos cobre a maioria dos casos sem cansar.
- Texto aberto é opcional, nunca obrigatório (mata a taxa de conclusão).
- A coleta vem ANTES da oferta — sem o motivo, não há oferta dinâmica.
- Conclusão alvo >80%. Abaixo de 70%, a pesquisa está longa ou opcional.

## Win-back (pós-cancelamento)
- **D7:** check-in genuíno, 1 CTA, sem pressão, link de reativação. É o pico de win-back.
- **D30:** só se houver gatilho real — atualização relevante de produto ou oferta pertinente. Sem isso, não mande.
- Benchmark de reativação: 5-10% dos cancelados em 90 dias.
