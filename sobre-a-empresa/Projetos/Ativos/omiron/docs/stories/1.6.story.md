# Story 1.6 — Gestão de Usuários pela Secretária

**Epic:** E1 — Fundação & Autenticação

**Quality Gate Tools:** [typecheck, lint, auth-audit]
**Complexity:** M
**Business Value:** High

---

## Story

Como secretária (Helen), quero cadastrar novos pacientes no sistema e gerar login/senha para eles, para que cada paciente receba acesso ao app desde a primeira consulta sem precisar de suporte técnico.

---

## Acceptance Criteria

1. Helen consegue criar um novo paciente informando: nome completo, email, telefone
2. Sistema gera senha temporária aleatória e envia automaticamente via email (Resend) para o paciente com link de acesso
3. Email de boas-vindas contém: login (email), senha temporária e link para o app
4. Paciente é obrigado a trocar a senha no primeiro login (flag `force_password_change`)
5. Helen vê lista de todos os pacientes cadastrados com: nome, foto, email, data de cadastro, status (ativo/inativo)
6. Helen consegue desativar (soft delete — não deletar) um paciente
7. Paciente desativado não consegue fazer login (Supabase Auth `disabled: true`)
8. Helen consegue reativar um paciente desativado
9. Helen NÃO consegue editar dados clínicos (diagnóstico, medicação, metas)

---

## Scope

### IN
- Formulário de cadastro de paciente (secretária)
- Criação de usuário no Supabase Auth + tabela `users`
- Envio de email de boas-vindas via Resend
- Listagem de pacientes (dados básicos)
- Ativação/desativação de pacientes
- Flag de troca obrigatória de senha

### OUT
- Edição de dados clínicos (apenas médico — Story 1.5)
- Cadastro de médico ou secretária (feito pelo próprio Ronan via Supabase dashboard)
- Importação em massa de pacientes

---

## Dependencies

- Story 1.2 (tabela `users`, Supabase Auth configurado)
- Story 1.4 (middleware de auth — secretária já autenticada)
- Configuração do Resend (API key necessária)

---

## Risks

- Email de boas-vindas pode cair no spam → Usar domínio verificado no Resend e bom texto de assunto
- Senha temporária exposta no email → Senha deve expirar após primeiro uso ou 24h; usar Supabase `inviteUserByEmail` como alternativa

## Dev Notes

### Criação de usuário via Supabase Admin

```typescript
// Usar Supabase Admin client (service role key) no servidor
import { createClient } from '@supabase/supabase-js'

const supabaseAdmin = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY! // NUNCA expor no client
)

// Criar usuário
const { data, error } = await supabaseAdmin.auth.admin.createUser({
  email: input.email,
  password: temporaryPassword,
  email_confirm: true, // pular confirmação de email
  user_metadata: { name: input.name, force_password_change: true }
})
```

### Template de email de boas-vindas (Resend)

```typescript
// src/lib/email/welcome.ts
import { Resend } from 'resend'

const resend = new Resend(process.env.RESEND_API_KEY)

export async function sendWelcomeEmail(
  email: string,
  name: string,
  password: string
) {
  await resend.emails.send({
    from: 'Clínica Omiron <omiron@clinicaomiron.com.br>',
    to: email,
    subject: 'Seu acesso ao Omiron está pronto',
    html: `
      <h2>Bem-vindo(a) ao Omiron, ${name}!</h2>
      <p>Seu acesso ao sistema de monitoramento da Clínica Omiron foi criado.</p>
      <p><strong>Email:</strong> ${email}</p>
      <p><strong>Senha temporária:</strong> ${password}</p>
      <p>Você será solicitado(a) a criar uma nova senha no primeiro acesso.</p>
      <a href="${process.env.NEXT_PUBLIC_APP_URL}/login">Acessar o Omiron</a>
    `,
  })
}
```

### Geração de senha temporária

```typescript
function generateTemporaryPassword(): string {
  const chars = 'ABCDEFGHJKMNPQRSTUVWXYZabcdefghjkmnpqrstuvwxyz23456789'
  return Array.from({ length: 12 }, () =>
    chars[Math.floor(Math.random() * chars.length)]
  ).join('')
}
```

})
