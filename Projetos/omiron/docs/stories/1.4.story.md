## Story

Como usuário do Omiron, quero fazer login com email/senha ou magic link e ser redirecionado automaticamente para a área correta do meu perfil (paciente, secretária ou médico), para que eu acesse apenas as funcionalidades do meu papel e os dados dos outros perfis sejam protegidos.

---

## Acceptance Criteria

1. Login via email/senha funciona para os 3 perfis
2. Login via magic link funciona (Supabase envia email com link de acesso direto)
3. Após login, redirecionamento automático por role:
   - `patient` → `/dashboard`
   - `secretary` → `/admin`
   - `doctor` → `/medico`
4. Tentativa de acessar rota de outro perfil retorna redirect para `/unauthorized` ou para a rota correta do usuário
5. Sessão persiste após refresh do browser (cookie httpOnly gerenciado pelo Supabase)
6. Logout limpa sessão e redireciona para `/login`
7. Middleware Next.js protege rotas autenticadas — usuário não autenticado é redirecionado para `/login`
8. Tela de login com campos de email/senha + botão "Entrar com link mágico"
9. Estado de loading durante autenticação (spinner)
10. Mensagem de erro clara em caso de credenciais inválidas

## Dev Notes

### Middleware de proteção de rotas

```typescript
// src/middleware.ts
import { createMiddlewareClient } from '@supabase/auth-helpers-nextjs'
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export async function middleware(req: NextRequest) {
  const res = NextResponse.next()
  const supabase = createMiddlewareClient({ req, res })
  const { data: { session } } = await supabase.auth.getSession()

  if (!session) {
    return NextResponse.redirect(new URL('/login', req.url))
  }

  // Verificar role e proteger rotas
  const { data: user } = await supabase
    .from('users')
    .select('role')
    .eq('id', session.user.id)
    .single()

  const pathname = req.nextUrl.pathname

  if (pathname.startsWith('/admin') && user?.role !== 'secretary') {
    return NextResponse.redirect(new URL('/unauthorized', req.url))
  }

  if (pathname.startsWith('/medico') && user?.role !== 'doctor') {
    return NextResponse.redirect(new URL('/unauthorized', req.url))
  }

  if (pathname.startsWith('/dashboard') && user?.role !== 'patient') {
    return NextResponse.redirect(new URL('/unauthorized', req.url))
  }

  return res
}

export const config = {
  matcher: ['/dashboard/:path*', '/admin/:path*', '/medico/:path*'],
}
```

### Criação de usuário (trigger no Supabase)

Ao criar usuário via `auth.users`, um trigger deve criar a entrada em `public.users`:

```sql
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.users (id, email, role, name)
  VALUES (NEW.id, NEW.email, 'patient', COALESCE(NEW.raw_user_meta_data->>'name', 'Novo Usuário'));
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE PROCEDURE public.handle_new_user();
```

O role `patient` é default. A secretária altera o role via painel admin (Story 1.6).
